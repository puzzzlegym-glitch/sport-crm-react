# Sport CRM — React SPA

React-переписування (Vite + React 19 + react-router-dom) наявного PHP/vanilla-JS застосунку CRM4Fitness. Бекенд (PHP/PDO/MySQL) залишається без змін — цей репозиторій замінює лише фронтенд, ходить на ті самі `api/*.php` ендпоінти.

## Запуск

```
npm install
npm run dev
```

Dev-проксі (`vite.config.js`) ходить на `fitness.neobot.pp.ua` — для продакшн-збірки бекенд має бути на тому самому домені, що й білд (`api/client.js` ходить відносними шляхами `/api/*.php`, без окремого налаштування домену).

## Інші команди

```
npm run build   # продакшн-збірка (dist/)
npm test        # vitest run
npm run lint    # oxlint
```

## Структура

- `src/api/` — обгортки над бекенд-ендпоінтами, по одному файлу на модуль (clients, invoices, products, trainers, ...) + `client.js` з центральною функцією `api(action, body, moduleKey)`
- `src/context/AuthContext.jsx` — сесія, права доступу (`canWrite`/`isOwner`/`isSuperAdmin`/`level`), активний клуб
- `src/components/layout/` — `AppLayout` (сайдбар+шапка), `ProtectedRoute`, конфігурація меню (`navItems.js`)
- `src/components/ui/` — спільні компоненти (Table з авто-мобільними картками, Pagination, Modal, Badge, FormGroup, ToastProvider)
- `src/hooks/` — `usePermissions`, `useShiftLock` (блокування дій без відкритої зміни каси), `usePlanLock`
- `src/pages/` — усі сторінки, кожна з власним CSS-файлом (порт відповідного `assets/css/*.css` з оригіналу)

## Відомі обмеження бекенду (не виправляються на фронтенді)

- Пошук клієнтів за текстовим запитом без цифр (напр. "Петренко") повертає всіх клієнтів клубу — зачіпає Клієнтів, продаж товару, ручну відмітку відвідування.
- Прихід товару зі статусом "Замовлено" одразу додається на склад, хоча має чекати підтвердження.
- `saas_api.php`'s `get_subscriptions` повертає 500 при непорожньому фільтрі статусу.

Детальніші нотатки — у пам'яті сесії розробки (react_rewrite_progress.md), не в цьому репозиторії.
